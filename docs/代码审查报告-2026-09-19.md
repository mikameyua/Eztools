## 二、人工深审发现的问题（静态工具全部漏报）——已修复

### 🔴 问题 1：`ConfigStore.Reset` 裸删用户配置，不可恢复（数据安全）

**位置**：`src/Eztools.Host/Config/ConfigStore.cs:144`
**问题**：`File.Delete(path)` 直接删。同一个类的类头注释写着"宁可留一个看不懂的文件，也不能把用户配置抹掉"（损坏时备份 `.corrupt-*`）——但用户**主动**点"恢复默认"（或工具误调用 `config reset`）时配置被裸删。原则自相矛盾，且误点没有挽回手段。
**修复**：改为 `File.Move` → `<toolId>.json.reset-backup-<时间戳>`，与 `.corrupt-*` 同款风格。
**验证**：set → reset → 文件已从配置位消失、备份存在、`config get` 回落默认值（实测通过）。

### 🔴 问题 2：`async void Save()` 无重入防护（并发）

**位置**：`src/Eztools.Desktop/SettingsWindow.cs`
**问题**：保存期间 `await PushConfigAsync` 让出 UI 线程，窗口仍可交互——**双击"保存"会并发两次**，两次写盘 + 两次推送交错。
**修复**：保存期间禁用「保存」「恢复默认」按钮，`finally` 恢复。

### 🔴 问题 3：`async void` 缺顶层异常兜底（可靠性）

**位置**：同上
**问题**：`async void` 的未处理异常没有调用方可接，会**直接崩掉整个托盘进程**（不只是丢一次保存）。保存主体虽有 per-field try/catch，但 `OnToolSelected()`（重新加载快照，含 IO）不在任何 try 内。
**修复**：拆出 `SaveCoreAsync()`，`Save()` 顶层 try/catch + 记日志 + 错误提示框。

### 🟡 问题 4：保存成功提示永远不可见（UX bug）

**位置**：同上
**问题**：`_hint.Text = "已保存 N 项…"` 写在 `OnToolSelected()` **之前**，而后者会把 `_hint` 重置成配置路径——提示被立刻覆盖，用户永远看不到。
**修复**：调换顺序（先重载快照，再写提示）。

### 🟡 顺带：`Reset` 无确认框 + 无自动化覆盖

"恢复默认"是破坏性操作，此前一键直达且**验收脚本 0 条断言**。已加：确认对话框（说明有备份）+ 无落盘配置时按钮无动作；reset 备份行为补了一条手工实测（见上）。

## 五、给手工验证的建议顺序（结合审查发现）

1. 托盘 →「设置…」打开窗口 → 看 Fluent 主题观感
2. 改一个值 → 保存 → **确认提示条出现"已保存 N 项"**（就是问题 4 修的点）→ `ezt config get` 对账
3. 双击快速点两次「保存」→ 不应出现异常（问题 2 修复点；按钮期间应为禁用态）
4. 点「恢复默认」→ **应弹确认框**（新加）；确认后配置文件变为 `.reset-backup-*` 备份
5. 长时间开着设置窗口时在另一终端 `ezt invoke` 工具 → 两者不应互相干扰（WinForms 循环 + 模态泵共存）
