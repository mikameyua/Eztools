## 2. 手工项

### M1 真机直贴（中文内容 + 前台还原）★ 核心

**为什么必须手工**：真实 `Ctrl+V` 注入会贴进"运行探针的那个终端"，自动化里做不到  
（与 W5 面板同款纪律 —— 可判定部分已抽成纯函数/降级路径，端到端注入留人眼）。

**前置**：托盘在跑（`_scratch/start-tray.cmd`）· `clip.enabled=true`。

1. 打开记事本（或任意文本输入处），输入一句中文：`直贴测试：中文内容与标点，ABC123`，  
   然后 `Ctrl+A` `Ctrl+C` 复制。
2. 按 `Ctrl+Alt+S` 唤出搜索窗。
3. 输入 `直贴测试`（或 `中文`）。
4. **判据 ①**：出现一条带 **⧉** 徽标的结果，副行形如 `来源 notepad.exe · MM-dd HH:mm`。
5. 按 `Enter`。
6. **判据 ②**：搜索窗**消失** → 记事本回到前台 → 内容**原样插入光标处**  
   （中文与标点逐字一致：`直贴测试：中文内容与标点，ABC123`）。

**失败时**：把状态行文案一并记录（它要么说"已复制（未能直贴…）"，要么说"已复制，但原窗口已关闭"）。

### M2 降级路径（无可用目标窗口）

**为什么必须手工**：探针覆盖了"降级**逻辑**"，"从真桌面唤出"是另一条真实路径。

1. 点一下**桌面空白处**（让前台是桌面），按 `Ctrl+Alt+S` 唤出。
2. 搜一条剪贴板内容，按 `Enter`。
3. **判据**：搜索窗**不消失**（用户还得看见这句话），状态行显示  
   `已复制（未能直贴：无可用目标窗口）`；此时手动 `Ctrl+V` 能贴出内容。

> ★ **此条 2026-10-04 首次真机执行时失败了**（窗口**静默消失**、无状态行）：根因是**判据错位**
> —— 把"桌面窗口"（`Progman`）当成了可粘贴目标，`RestoreForeground` 对它返回 true ⇒ 代码误判成功。
> 已修（`踩坑全集.md` §2.42）。**若你再次看到"窗口直接消失"，那是回归**，请立刻告诉我。

### M3 与剪贴板面板同时开（WAL 并存）

1. 打开剪贴板面板（`Ctrl+Alt+C`），**保持不关**。
2. 在搜索窗里搜同一条内容。
3. **判据**：两边都能出结果、都不报错（同一 SQLite 库靠 WAL 并存 —— W5-c 已验证形态，  
   本项验的是"启动器作为第二个读者"）。

### M4 隐私闸仍然生效（暂停捕获 / 黑名单）—— 不新增暴露面

**背景**：W10 的 clip provider **只读** W5 那个库 ⇒ 被隐私闸拦下的内容根本不在库里 ⇒ 搜不到。
所以本项验的是"**provider 没有绕过入库侧的闸门**"（拦截职责仍在 W5，不重复实现也不绕过）。

**路径 A：暂停捕获（推荐 —— 运行时开关，点一下立刻生效，不改配置、不重启托盘）**

1. 托盘图标右键 → **「剪贴板历史」** → **「暂停捕获（隐私模式）」**
   （点完应弹气泡 `捕获已暂停（隐私模式，期间复制不入库）`）。
2. 记事本里输入 `隐私暂停测试 QX741`，`Ctrl+A` `Ctrl+C`。
3. 托盘右键 → 剪贴板历史 → **「恢复捕获（当前已暂停）」**（气泡 `捕获已恢复`）。
4. 唤出搜索窗，搜 `隐私暂停测试` ⇒ **判据：搜不到**。
5. ★ **正向对照（必做）**：再复制一段 `恢复对照 RY852` ⇒ 搜索窗里**能**搜到。
   （少了这一步，"搜不到"可能是别的原因造成的，断言就变成恒真）

**路径 B：真黑名单（⚠️ 要它生效必须重启托盘）**

1. `clip.blacklist` 填 `notepad.exe`（可让 AI 代写）。
2. ⚠️ **重启托盘**（关掉托盘 + 双击 `start-tray.cmd`）：`clip.blacklist` 只在**启动**与
   **设置窗口保存**时被读入 —— CLI 改配置文件**不会**热生效（托盘没有配置文件的文件监视器）；
   若直接从**设置窗口**改，则保存即生效、无需重启。
3. 记事本复制 `黑名单直测 ZP963` ⇒ 搜索窗搜 `黑名单直测` ⇒ 搜不到。
4. 还原 `clip.blacklist` + 再重启一次托盘。

### M5 `>` 在中文输入法下的输入

1. 切到中文输入法（如微软拼音）。
2. 唤出搜索窗，直接输入 `>`（`Shift` + `.`）。
3. **判据**：列出三条命令（`锁屏` / `休眠` / `清空回收站（不可恢复）`），带 **⌘** 徽标、按表序。
4. 输入 `>` + `清` ⇒ **判据**：只剩「清空回收站（不可恢复）」。

**失败时**：若 `>` 被输入法吞掉 ⇒ **改用 `cmd:`**（W10-c 已落地，与 `>` 逐字同语义，无须 Shift/切半角）。

### M6（可选）命令真的执行

⚠️ **有真副作用，自行决定**：`>锁屏` 按 `Enter` 会真的锁屏（等同 `Win+L`）；  
`>清空回收站` **不可恢复**（标题已带警示，这是刻意的）。

### M7 图片条目提字（W10-c）★ 新增

**为什么必须手工**：提字成功后走的是**同一条直贴链**（真注入 Ctrl+V）—— 机器侧只能验到
"提字方法真能出字"（verify-desktop 拿**已知文字**的样图跑真 OCR），
**"文字有没有贴进你原来那个窗口"只有人眼能判**。

1. 先用 `Win+Shift+S` 截一块**带文字的图**（比如本清单里的一段话）。
2. 打开记事本，光标点进正文区。
3. `Ctrl+Alt+S` 唤出搜索窗 → 输入 `图片` → 应列出图片行（**⧉** 徽标，主行像 `图片 1920×1080 · 240 KB`）。
4. 选中刚截的那张 → `Enter`。
5. **判据**：搜索窗消失 → 记事本回到前台 → **图里的文字被逐字贴进光标处**（不是图片本身）。

**失败时的三种文案**（都在状态行，且原因**分得开** —— R1 纪律，不把"我没能力"说成"你没内容"）：
`提字失败：本机没有可用的 OCR 语言包（…）` / `提字完成，但这张图里没识别到文字` / `提字失败：图片文件已不在（…）`。

> 顺带确认一条：搜 `图片处理` 这类词**仍走普通文本检索**（触发词只精确匹配，不吞查询）。

> ★ **一条良性副作用（观察记录）**：提字出来的文本会被托盘**自己的监听采回库**（`id=188`）——
> 因为直贴链第一步就是 `Clipboard.SetText`。与 M1 的直贴同款（`id=180` 的 `copyCount=18` 就是这么来的）。
> 同内容会按 hash 去重合并（只涨 `copyCount`，不涨条数）⇒ **不会撑库**，但要知道它会发生。

> **M4 的判据为什么算数**：本项目纪律是"静默类判据必须配正向对照" —— 只验"搜不到"会**假绿**
> （采集链死了、托盘没跑，同样什么都搜不到）。这次日志同时给出了**两侧**：
> **暂停窗口内 = 空**（说明暂停真的挡住了）+ **恢复之后 = 有**（说明采集链本身是活的）。
> 两侧齐全才排除了"其实整个采集都坏了"这条替代解释。

## 4. 症状速查

| 现象                        | 先查什么                                                                                            |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| 搜不到任何剪贴板内容                | 先搜一个**刚复制过**的词；`ezt clip list` 看库里到底有没有。库里没有 ⇒ 是 W5 采集链（`clip.enabled` / 热键 / 监听）的问题，**不是 W10** |
| 有结果但 Enter 没反应            | 看状态行文案：`已复制（未能直贴：…）` = 降级（**正常**）；完全无文案 = 异常，附日志                                                |
| `>` 打不出来                  | 输入法状态（见 M5）                                                                                     |
| 关了 `clip.enabled` 仍能搜到剪贴板 | **再唤出一次**（热生效走"配置变更 ⇒ 重建搜索窗"）；仍不行附日志                                                            |
| 命令列不出来                    | 确认前缀是**半角** `>`；`⌘` 徽标在不在                                                                       |
| 图片搜不到（W10-c）             | 图片条目**没有文本内容**，普通检索永远搜不到它 —— 要打**精确**的 `图片`（或 `img`）才列出最近图片                      |
| 热键没反应                     | `scripts/probe-hotkey-free.py`（外部程序占用热键是已知环境冲突，先排除它）                                            |
