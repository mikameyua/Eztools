## M 项（面板 · W5-b）

### M1 ★ 直贴端到端（还原前台 + Ctrl+V 注入）

探针把 Ctrl+V 真注入抑制了（贴进运行探针的终端不可接受），所以这一环只能手工：

1. 在记事本/编辑器里把光标放到任意位置。
2. 复制几段文字（含一段中文、一段英文）。
3. 运行托盘（热键 Ctrl+Alt+V）唤出面板，或 `Eztools.Desktop.exe --probe-clip-panel` 先造点历史。
4. 选中一条 → **Enter**。
5. **判据**：面板收起；内容出现在原窗口的光标处（不是剪贴板里等你手动 Ctrl+V）。
6. 反向：直贴前把原窗口关掉再 Enter → 判据 = 面板收起 + 托盘气泡"已复制，但未能还原原窗口"（降级路径可见，不静默）。

> **自动化面**：`--probe-clip-panel` 已覆盖「过滤到恰 1 条 → Enter → 面板隐藏 + 剪贴板逐字相等」。
> 未覆盖的只剩「真 Ctrl+V 注入到目标窗口」，即本 M1。

### M2 ★ 键盘全链路（真人按键）

> ★ **2026-09-27 换实现**：输入框 = 宿主化**原生 EDIT**（`NativeInputBox`，走 IMM32）。
> 自建供字层（直通字符合成 / `GetAsyncKeyState` 轮询 / LL 钩子 / `PreviewTextInput` 拦截）
> **已全部删除** —— 旧版"面板内打不了中文"的限制<b>不再存在</b>，中文走系统输入法正常上屏。
> 键位归属：**文本编辑归原生控件，命令键由它上报**（见 `NativeInputBox.Command`）。

面板唤出后逐项手测（判据见括号）：

- 打字（**英文 / 大写锁 / 中文拼音组合条→上屏**）→ 搜索实时过滤（防抖 30ms）。
  ✅ 英文与注入路径已自动化（`--probe-clip-panel` 走真键 Enter，`--probe-search-summon` 读 `vkAfterLetter`）；
  **中文组合上屏归本项手测**（自动化摸不到 IME 组合条）。
- ↓/↑ 移动高亮（焦点不掉进列表，继续打字仍进搜索框）。
- Enter 直贴选中项；无选中项时 Enter 直贴第一条。
- Ctrl+Enter 仅复制（面板**不**收起，状态行回显"已复制（未直贴）"）。
- Del 删除选中条目 —— ★ **行为收紧（2026-09-27）**：只在**输入框为空**时删条目；
  输入框有字时 Del 是正常的"向后删字符"。旧版无条件删条目属于"快捷键凌驾于文本编辑"，已修。
- Ctrl+P 置顶/取消（📌 标记切换，置顶条目排到最前）。
- Ctrl+C 复制选中内容 —— ★ 同理：**有选中文字时**复制文字（原生行为），**无选区时**才复制条目。
- Esc / X / Alt+F4 / 点外面 → 全部只是收起；**再次热键/探针唤出必须可用**（§2.25① 契约）。

### M3 图片条目：缩略图 + OCR 提字（FR-15）

1. 截屏（Win+Shift+S）或复制任意图片 → 面板出现该条目。
2. **判据（缩略图）**：48px 缩略图显示、行高不塌、滚动 200 条不卡（虚拟化）+ Enter 直贴图片到画图/聊天窗口。
3. **判据（OCR 提字）**：右键**图片条目** → 菜单「提取文字（OCR）」可点 → 状态行回显"已提取文字并复制到剪贴板"→ 粘贴得到文字。
   - 反向：右键**非图片条目** → 该项**置灰**（不是消失 —— 置灰才表达"有这功能但这条用不上"）。
   - 语言包缺失时：状态行 + 托盘气泡给 `Add-WindowsCapability` 引导，**不得**谎报"图里没有文字"（R1）。

> **自动化面**：`--probe-clip-ocr` 已覆盖三条判据（非图片不可用 / 图片可用 / 真实菜单点击后剪贴板拿到样图文字；
> 样图文本 "EZTOOLS OCR 2026"，判据与 `ezt ocr probe` 同口径）。未覆盖的只剩"真鼠标右键"这一下。

### D1 跟随光标弹出 ★ 唯一有真实风险的一项

**为什么单列**：定位走的是**物理像素** + "光标所在那台显示器的工作区"，混合缩放/副屏正是最容易出错的地方（W4-b 就在副屏坐标原点上栽过）。

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | 光标移到**主屏左上角**附近 → 按 Ctrl+Alt+V | 面板出现在光标**右下**方，完整可见 |
| 2 | Esc 收窗；光标移到**主屏右下角**（贴近任务栏）→ 唤出 | 面板**向左上翻边**，仍**完整可见**（不得被屏幕边缘裁掉、不得只露半截） |
| 3 | 光标移到**副屏**任意位置 → 唤出 | 出现在**副屏**光标附近；**不得跳到主屏**、不得跑到 (0,0) 附近 |
| 4 | 若两屏**缩放不同**（如主屏 100% / 副屏 150%），重复第 3 步 | 面板尺寸与落点仍正确（不出现半屏大 / 缩成一条） |
| 5 | 连续唤出 3 次，每次前把光标挪到不同位置 | 每次都跟随；第二次起**不得停在上次的位置** |
| 6 | 光标放在副屏最右下角 → 唤出 | 翻边到光标左上，且**不跨越显示器边界** |

> 判据一句话：**面板必须完整落在光标所在那台显示器的工作区内**。
> 记录：哪几步不合格 + 当时的屏幕布局与缩放值 + 截图。

### D2 黑名单实测

```
:: 1) 配置黑名单（拿记事本当靶子：安全、好复现）
ezt config set desktop clip.blacklist "notepad.exe"

:: 2) 确认写进去了
ezt config get desktop clip.blacklist

:: 3) 重启托盘（配置在启动时装载）：托盘图标右键 → 退出，再双击 D0-1 那条 exe

:: 4) 打开记事本，输入一段独一无二的文本（例：BLACKLIST-TEST-7788 中文也要有），Ctrl+A → Ctrl+C

:: 5) 等 2 秒后验证
ezt clip search BLACKLIST-TEST-7788    ← 期望 0 条
```

**反向对照（证明第 5 步不是"什么都搜不到"）**：改用**浏览器**复制同一段文本 → `ezt clip search BLACKLIST-TEST-7788` **应能搜到**。

**日志旁证**：`findstr /C:"黑名单命中" %LOCALAPPDATA%\Eztools\logs\host-ezt-desktop-*.log` 应出现 `剪贴板黑名单命中，未保存（notepad.exe）`；重启后的启动行应变成 `黑名单 1 个`。

### D3 UIPI 提权降级

需要**管理员**窗口。

> 下面命令里的 `clip` 是 **Windows 自带的 `C:\Windows\System32\clip.exe`**（把 stdin 写进剪贴板），
> **不是**本项目的 `ezt clip` 子命令 —— 要的正是"由一个**提权**进程写剪贴板"这个前提。

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | Win+X → "终端(管理员)" | 提权窗口 |
| 2 | 执行 `echo UIPI-TEST-9911 \| clip` | 无报错 |
| 3 | 等 2 秒 → Ctrl+Alt+V 唤出面板 | 出现占位条目「**[提权进程 cmd.exe 复制的内容未保存]**」+ **一次性**气泡提示"读不到…已记一条占位条目" |
| 4 | `ezt clip search UIPI-TEST-9911` | **0 条** ← 本项真正的安全断言：内容确实没入库 |
| 5 | 再复制一次提权内容 | 仍记占位条目，但**不再弹气泡**（一次性语义） |
| 6 | 反向：在**普通** cmd 里 `echo NORMAL-TEST-9911 \| clip` | 正常入库且搜得到；**不得**记成占位条目 |

> 第 3 步若无反应：先看日志有没有 `UIPI 降级` 行。没有则说明那次读取**没失败**（owner 判定不同），
> 记下 Windows 版本 + 第 4 步结果再判断，别直接判失败。
