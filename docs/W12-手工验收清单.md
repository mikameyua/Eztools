## §A 自动化（三条命令）

`@bash
dotnet run --project src/Eztools.Cli -- selftest            # 基线 336/0，只增不减
python -I -X utf8 -u scripts/verify-desktop.py              # 基线 274/0
python -I -X utf8 scripts/check-doc-refs.py --strict        # 期望 rc=0
`@

**判据**：selftest 末行 FAIL 0 且用例数 ≥ 336 + 本波新增；verify-desktop FAIL 0 且断言数 ≥ 274 + 本波新增；check-doc-refs rc=0。任一 `[FAIL]` ⇒ 不通过。

## §B 必须保留人工的项（6 项）

### B1 · 空查询默认视图真机链路

**为什么必须人工**：热键 → 托盘 → 真窗口 → 真键盘这条链是自动化禁区（W10 探针纪律）；且"最近使用"的数据只有**真人用过几次应用**之后才有内容。

| 步骤 | 操作 | 预期 | 判据 |
|---|---|---|---|
| 1 | 正常用托盘/开始菜单启动 2~3 个应用（例如记事本、计算器），每个用一次 | —— | 前提步骤 |
| 2 | 热键唤出搜索窗（**不输入任何字**） | 结果列表直接列出最近用过的应用；右位显示 `最近使用 N` | 有行且 N ≥ 1 ⇒ 通过；空白 ⇒ 失败 |
| 3 | 对着其中一行按 **Enter** | 应用被打开；窗口收起 | 打开 ⇒ 通过 |
| 4 | 再唤出 → 选中一行按 **Ctrl+Enter** | 资源管理器定位到该快捷方式 | 定位 ⇒ 通过 |
| 5 | 再唤出 → 选中一行按 **Ctrl+C** | 状态行显示 `已复制路径：…`，剪贴板是目标路径 | 通过 |
| 6 | 输入任意一个字（如 `a`） | 默认视图**立刻退出**，变成普通搜索结果 | 通过 |

### B2 · Tab 动作菜单（drill-down）真机

**为什么必须人工**：Tab 是否被真正吞掉、动作行的**视觉可达性**（行高/数量/滚动）只有人眼能确认。

| 步骤 | 操作 | 预期 | 判据 |
|---|---|---|---|
| 1 | 唤出搜索窗，随便搜一个**文件**（如 `readme`） | 有文件行 | 前提 |
| 2 | 按 **Tab** | 列表整体**替换**为该行的动作行（打开 / 定位 / 计算哈希并复制 / 统计字数 / 速览），徽标 `⚙` | 出现 5 条动作 ⇒ 通过 |
| 3 | 按 **Tab** 或 **Esc** | 回到原来的结果列表，且**仍选中刚才那一行** | 回得去 ⇒ 通过 |
| 4 | 再按 Tab 进动作菜单 → 打一个字 | 自动退出动作模式并给出该字的搜索结果 | 通过 |
| 5 | 进动作菜单 → 对**应用行**按 Tab | 只有 2 条（打开 / 定位），**没有**哈希/字数/速览 | 通过 |

### B3 · 工具动作真链路（哈希 / 字数 / 速览）

**为什么必须人工**：真剪贴板 + 真文件 + 真面板，三者都是自动化边界（探针跑在终端里，真注入会贴进终端）。

| 步骤 | 操作 | 预期 | 判据 |
|---|---|---|---|
| 1 | 搜索窗搜到一个**已知内容的小文件** → Tab → 选「**计算哈希并复制**」→ Enter | 状态行（或托盘气泡）显示 `sha256: <hex>`；**剪贴板里就是这一行** | 剪贴板内容 == 状态行摘要 ⇒ 通过 |
| 2 | 把步骤 1 的哈希与 `Get-FileHash -Algorithm SHA256` 对比 | 一致 | 一致 ⇒ 通过 |
| 3 | 同一文件 → Tab → 「**统计字数**」→ Enter | 显示 `字符 N · 词 N · 行 N`（与实际大致相符） | 有数字 ⇒ 通过 |
| 4 | 资源管理器里**选中**该文件 → 搜索窗搜到它 → Tab → 「**速览**」→ Enter | 速览面板打开并显示该文件内容；搜索窗收起 | 面板内容 == 该文件 ⇒ 通过（这一步验 `inputPaths` 传对了） |
| 5 | 对**已删除**的文件（先在资源管理器删掉它，索引还没同步时）重做步骤 1 | 状态行显示 `执行失败：…`，**窗口不收起**（可以继续操作） | 通过 |
| 6 | 连点两次「计算哈希并复制」 | 不重复执行、不弹两个结果（`_toolBusy` 生效） | 通过 |

### B4 · 空态文案三态

**为什么必须人工**：状态行是**一句话**，措辞是否真的引导人（而不是自说自话）只能人判断。

| 步骤 | 操作 | 预期 | 判据 |
|---|---|---|---|
| 1 | 有最近使用记录时唤出 | 左位「输入以搜索 · Enter 打开 · Ctrl+Enter 定位 · Ctrl+C 复制 · **Tab 更多动作**」；右位「最近使用 N」 | 与设计方案 D6 逐字一致 ⇒ 通过 |
| 2 | `ezt config set desktop launcher.usage false` → 重启托盘 → 唤出 | 列表为空；右位显示「「图片」看最近剪贴板图片 · 「>」看系统命令」 | 通过 |
| 3 | 恢复 `ezt config unset desktop launcher.usage` → 重启托盘 | 视图恢复 | 通过 |
| 4 | 制造 apps 索引读不到（例如把开始菜单夹具目录改名）→ 唤出 | 右位显示**错误原文**（不是静默空） | 显错 ⇒ 通过；什么都不说 ⇒ 失败 |

> ⚠ 步骤 4 若不方便造，可跳过并在 §C 记录「未验」——**不要**用"没看到错误"当作通过。

### B5 · 既有按键链与搜索行为回归

**为什么必须人工**：既有链是"肌肉记忆"，回归只有手能发现。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 搜索 → **↓/↑** 移动选中项 | 选中项正常移动，焦点仍在输入框 |
| 2 | **Esc** | 收窗 |
| 3 | 无结果时按 **Enter** | 无动作、不崩（既有行为） |
| 4 | **Del**（输入框为空时） | 不进入动作菜单、不触发删除（既有：放行给 EDIT） |
| 5 | **Ctrl+P**（W5 片段置顶） | 行为与 W11 一致（不被本波影响） |
| 6 | 普通搜索（文件/应用/`>` 命令/`图片`） | 与 W11 一致，无新增卡顿 |

### B6 · 触发词发现性是否真的"被发现"

**为什么必须人工**：本波的 b 项就是**为人**做的；只有人回答"我下次会打 `图片` 吗"。

| 步骤 | 操作 | 预期 | 判据 |
|---|---|---|---|
| 1 | 清空输入框，看右位提示 | 提示串完整可见（不被裁切） | 完整 ⇒ 通过 |
| 2 | 照提示打 `图片` | 出现最近剪贴板图片 | 通过 |
| 3 | 照提示打 `>` | 列出全部系统命令 | 通过 |
