## 1.5 W8 · 可用性回填小波（2026-10-02 增补）

> **来源**：W7 实机验收（2026-10-02）。两则缺陷都不是"想要新功能"，而是"已宣称可用的功能实际被阻断"。
> 台账登记见 `docs/未完成项与待决清单.md` 头部（原状态 🟡 待立项（W8 候选）→ 现 ✅ 已立项（W8））。

| # | 项 | 性质 | 一句话理由 |
|---|---|---|---|
| B1 | **索引状态误报 + Core 一键启动** | 真 UX 缺陷（阻断） | Core 未跑时把"索引不可用"报成"正在建索引…"，**用户永远等不到建好**，且不知道要去启动 Core ⇒ 整个文件搜索入口事实上不可用 |
| B2 | **启动器配置热生效** | 一致性缺陷（误导） | `launcher.alias` / `launcher.usage` / `launcher.providers` 改完需重启托盘；用户实测 `usage=false` 落盘后 usage.json **仍在增长** ⇒ 配置写了不生效 = 静默说谎 |

**设计方案**：`docs/W8-可用性回填-设计方案.md`（v2.0 精简版）。

**状态**：✅ **已落地（2026-10-02）**。改动面 = **6 个文件（含 2 个新建：`CoreAvailability.cs` / `CoreLauncher.cs`）/ 0 新配置 / 0 新协议字段** ⇒ 不破任何既有约定（`src/Eztools.Index/**` 与 `src/Eztools.Core/**` **均零改动**）。落地记录（含 9 条实施偏差与原因）见该文 §7。

### 为什么不适用 §0 的三条筛选标准

W8 **不是新功能**，是把 W7 已经算作"完成了"的能力修回"真的可用"。用三条标准对账会得出错误结论，说明如下：

| 标准 | B1 索引状态误报 + Core 一键启动 | B2 配置热生效 |
|---|---|---|
| ① 一天至少用得上一次 | ✅ **超频**——每次"没先启动 Core 就搜文件"都命中，且**一旦命中就是 100% 阻断**（不是"不好用"，是"完全不能用"） | ✅ 每次改配置都命中（改 alias/关 usage/调 providers） |
| ② 复用已验证底座 | ✅ 全复用：`CoreMftClient` 已有精确文案与结构化码 · `VolumeClassifier.FailureText` 已有可读文案 · `CoreCommand.StartAsync` 已有 `Verb="runas"` 提权实现 · 状态行与 `_volumesLine` 已有出口 | ✅ 复用：搜索窗已有的"重建"路径（关窗再唤出即重建）+ 配置解析链 |
| ③ 无现成替代品 | ✅ 无——这是本产品自身链路的洞 | ✅ 无 |

> **判据说明**：三条全中却**不单独立项**，是因为按 `docs/代码审查规范与流程.md` §3.3 / §3.9 的口径，
> "**降级/告警类信号必须有可达出口**"是**红线级硬约束**，不是"要不要做"的取舍 —— B1 是这条红线在 W7 里的漏网实例，
> **修复属欠债清偿，无立项裁量空间**。W8 只是给它一个波次容器与验收面。

### W8 的边界（预防范围膨胀）

- B1 与 B2 **同属"配置/状态与实际不一致"**（B1 = 状态说谎，B2 = 配置说谎），共用同一套"**必须说得清为什么**"文案纪律与"**变更后可见**"出口纪律 ⇒ 合并成波，**验收面一起设计**。
- **不做**：`ezt-index` 自举重试机制（B1 的"第二半"）—— 它涉及 `src/Eztools.Index/**` 改动，而 W7 §10.1 第 27 行把该目录列为"本波不碰"。**改用一个不破该约定的等效手段**：`ezt-index` 自举只在 `Program.cs:88` 跑一次，而 `SearchIndexProcess` 本来就是"懒启动 + 死则下次请求自动重启" ⇒ 把索引进程**重启一次**（置空引用 + 重建搜索窗）即可让它重新自举。**这也顺带让 B1 的收尾与 B2 的生效共用同一个动作**（详见设计方案 §2.1）。
- **不做**：Core 的常驻自启/服务化（用户明确要求提权必须过 UAC）。
- **不做**：任何形式的"静默拉起 Core"——**UAC 必过**是本项的红线。

## 2. 明确不做（防止反复重提）

| 功能 | 理由 |
|---|---|
| 屏幕标尺 / 量角器 | 低频，用时开现成工具即可 |
| QR 码生成 | 偶发，手机/浏览器自带 |
| hosts 切换 | 频率配不上特权层复杂度（core 协议要加写文件白名单，暴露面不小）；SwitchHosts 现成 |
| 启动项管理 | 同上；PowerToys 现成 |
| 截图标注编辑器 | Snipaste 现成，高成本低差异化 |
| 截图翻译 / 表格转 Excel | 高成本低频；W4 OCR 提字已够用 |
| 键盘重映射 / 全局文本替换 | **永久排除**：键盘链 §2.25~§2.30 刚以"换实现"收口，不得再碰 |
