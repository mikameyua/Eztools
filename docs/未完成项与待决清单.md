## 2. 逐项：为什么做不了 + 替代方案

### A1. 宿主事件总线 —— 🔴 信息缺失（P4 里唯一的真空白）

**证据**：全文档只有两处提到它（§12 的 P4 清单 + §12 末一句），`grep` 全仓 **无方法名、无订阅语义、无载荷 schema**。

**为什么做不了**：不是技术难，是**没人定义过它是什么**。我现在能写出十套自洽的发布/订阅协议，
但没有一套能被验证为"你要的那套"——这正是要避免的"发明需求"。

**替代方案**：

| 方案 | 内容 | 取舍 |
|---|---|---|
| **① 内部事件（推荐）** | 只做"宿主 → 托盘/设置 UI"的事件，**不开放给工具订阅**；复用已有的 `ToolQuarantined` / `ResidentSnapshot` 那套 `event Action<T>` 模式 | 成本 1 天，解决"UI 要刷新但只能轮询"的真实痛点；不引入弱类型消息总线 |
| ② 工具可订阅 | 定义 `host.events.subscribe` + 事件名 + 载荷 schema | 会变成弱类型总线，且**当前没有工具需要它**（YAGNI）→ 幽灵代码风险高 |

**推荐 ①**。理由：现有 UI（托盘/设置页）确实靠"手动刷新"（托盘菜单有"刷新"项），这是**已存在的需求**；
而"工具订阅事件"是**想象出来的需求**。先做前者，后者等有工具提出来再说。

### C2. 全表句柄扫描 1~2 分钟 —— ✅ **已修复（2026-09-21）**

**证据（修复前）**：§20.4 已知限制：10 万+ 条目逐个 `OpenProcess`/`DuplicateHandle`。
`--timeout 300` 已能跑通，所以不是"不能做"而是"慢"。

**原推荐**：按 pid 分桶并行（PowerToys 也在做类似优化）。

**⚠️ 实际落地偏离了原推荐（必须先说明，再执行）**：

| 版本 | 做法 | 结果 | 根因 |
|---|---|---|---|
| v1 | pid 分桶 + 每桶 worker + 主线程 `thread.Join(30s)` | `rc=2 elapsed_ms=600294`（挂满 600s） | **`Join(timeout)` 不能替代看门狗**：`NtQueryObject` 挂住的是 worker 线程，主线程睡在 Join 上时**没有任何线程能通知它跳过**；8 个 worker 各自挂住 → 累计等满 |
| v2 | pid 分桶 + `AbandonCurrent` + 主线程看门狗 | 仍 600s | ① `Tick()` 同时写 `_progress` 与 `_lastSeen`，`Stalled()` 判据永远为假；② **"整桶放弃"丢掉该进程全部句柄**——比原实现更差 |
| **v3（最终）** | **按下标区间并行** + **每区间一个监督线程** + 可重启 worker | **8306 ms** ✓ | 见下 |

**为什么改区间并行**：既有的 `NtQueryObject` 挂起对策（清单 C3，明确不改）要求**另一个线程**观察到游标停滞 →
`SkipOne()` 推过挂起点 → **开新线程**从新位置继续。把原单线程算法**逐行复制**到 N 个互不重叠的 `[start, end)` 区间上，
每个区间自带一个监督线程，**挂起影响面仍是 1 个句柄**（与原实现完全一致）；而 pid 分桶会把它放大到"一个进程的全部句柄"。

**影响**：加速 **14×**；挂起隔离粒度**不退化**；结果正确性对账 `count=488 / returned=488 / distinct pids=47 / malformed=0`；

## 7. 两类**非项目缺陷**的限制（影响"能否验证"，不影响"能否用"）

1. **本机 WorkBuddy 环境的 safe-delete shim**：一次工具调用内累计删除 >1000 文件会触发批量确认 →
   验收脚本第一步 `rm -rf` 残留时**静默挂死**（实测 9 分 49 秒零输出）。
   解法：分批预清理（<1000/次）；**切勿** `env -u CODEBUDDY_SESSION_ID` 绕过（会 fail-closed，
   让验收报出 18 条"看起来像代码回归"的假失败）。已记入跨项目记忆。
2. **提权原语的验证边界**：需管理员令牌的 4 项自动化不了（会话起不出提权进程），
   只能手测；且 `readMft` 正向与 M4 判据在自动化里是盲区——**P3 的两个真 bug 恰恰是手测抓出来的**。
   这是"自动化覆盖不到就必须靠人"的诚实记录，不是待修项。
