## 为什么合并

本文档原名《Eztools 插件体系设计方案》，在需求澄清过程中经历了 17 次章节级修订，其中 §1–§15 已被 §16（重新框定为"工具集合"）与 §17（技术选型调研）取代，正文自相矛盾、不再适合作为权威设计依据。

需求的最终形态是：**Eztools = 类似 PowerToys 的一体化工具集合，不是插件平台**。据此，所有面向"第三方生态"的设计（多源 Feed、包格式、签名、信任状态机、沙箱）均已砍除。技术选型也从早期外推的 Electron + TypeScript 修正为 **C# / .NET + WinUI 3 宿主 + Python 独立进程工具**。
