## 二、逐产品设计模式（源码取证）

### 2.1 PowerToys —— "每模块一页 + 搜索直达 + 冲突中心"

- **导航**：`ShellPage.xaml` 顶部 `AutoSuggestBox`（SearchBox，L107-115）——输入即出建议项（`SuggestionItem` + 模板选择器：默认结果/无结果/"显示全部"），点建议**直接跳到对应页面/设置项**。左导航为模块平铺清单（`Views/` 下 25+ 个 `XxxPage.xaml`，一模块一页），前置 Dashboard + General 两页。
- **热键控件**：`Controls/ShortcutControl/ShortcutControl.xaml` —— 常态是**只读的按键徽章预览**（ItemsControl 逐键渲染）+ SubtleButton，点击开**对话框进入录制态**（PreviewKeyDown 捕获）。用户从不手打组合键文本。
- **热键冲突**：不止控件级——有整套子系统：`Services/GlobalHotkeyConflictManager.cs`、`Helpers/HotkeyConflictHelper.cs`、`Settings.UI.Library/HotkeyConflicts/`（AllHotkeyConflictsData / HotkeyConflictGroupData / ModuleHotkeyData…）。**跨模块冲突有集中索引与响应对话框**（HotkeyConflictResponse），不是各页面自己散着判。

### 2.2 ShareX —— "热键是一等窗口"

- 新版 UI 把热键管理做成**独立窗口**（`ShareX/Presentation/HotkeySettings/HotkeySettingsWindow.axaml`，MVVM：`HotkeySettingsViewModel`），与常规设置分离：
  - 顶部工具栏：Add / Remove / Edit / Duplicate / 上移 / 下移 / Reset；
  - 全局禁用时显示**警告横幅**（带一键启用按钮）；
  - 主体 = `任务 | 热键` 两列列表，每行热键是 `hotkey-capture` **录制按钮**；
  - 编辑单个热键的任务设置走 Edit 对话框。
- 启示：热键条目多、冲突多时，"列表 + 行内录制 + 工具栏"比"表单字段"更可扩展（ShareX 的热键可增删，Eztools 当前固定 8 条，形态介于两者之间）。

### 2.3 CopyQ —— "图标分类左列表 + Shortcuts 独立类 + 提交制"

- `ConfigurationManager::initTabIcons()`（configurationmanager.cpp L158-169）：左列表固定 9 类——General / Layout / History / Tray / Notifications / Tabs / Items / **Shortcuts** / Appearance，每类带图标；**插件页挂在 Items 下**（`initPluginWidgets`，含启用状态 checkbox）。
- 热键：`gui/shortcutbutton.{h,cpp}`（捕获按钮）+ `shortcutdialog` + `shortcutswidget`（图标|命令|快捷键 三列，逐命令一行）。
- 保存模型：**OK/Cancel 模态提交制**（QDialogButtonBox），非自动保存。
- 启示：分类名用"功能名词"而非"波次/技术名"；插件设置页由插件自带 UI 但嵌在统一分类体系内（与 Eztools"schema 驱动 + 宿主渲染"同思路，CopyQ 让插件自带 Qt Widget，Eztools 用 schema 约束——后者更统一）。

### 2.4 Flow Launcher —— "热键独立 pane + 插件设置页自带 UI"

- `SettingPages/Views/`：SettingsPaneGeneral / **SettingsPaneHotkey** / SettingsPanePlugins / SettingsPanePluginStore / SettingsPaneTheme / SettingsPaneProxy / SettingsPaneAbout —— 顶部主热键+插件搜索热键各自有 pane。
- 插件设置：`PluginSettingsWindow.xaml` 通用窗口 + 每插件自带 `SettingsControl.xaml`（如 Calculator/CalculatorSettings.xaml）。
- 启示：插件多时"插件列表 + 每插件设置页"是通用解；对 Eztools W7（Launcher+插件）是现成蓝本。

## 三、与 Eztools 现状（方案 B）的对齐验证

| 设计决策 | 四家共识 | Eztools B 现状 | 结论 |
|---|---|---|---|
| 左列表按功能域分类导航 | 四家全部（PowerToys 模块页 / CopyQ 9 类 / Flow pane / ShareX 分窗） | ✅ 全局设置 5 功能域 + 工具组 | **命中共识** |
| 热键有专门统一入口 | 四家全部（三家独立分类/pane，ShareX 独立窗口） | ✅ 热键中心聚合页 | **命中共识**，且宿主 5+工具 3 统一视图比 CopyQ（按命令散）更聚合 |
| 热键 = 按键录制，绝不手打文本 | 四家全部（ShortcutControl / hotkey-capture / ShortcutButton / Hotkey pane 录制） | ❌ 仍是自由文本 TextBox | **最大差距** → 方案 C-4（录制控件）优先级应提为 C 波次第一项 |
| 冲突集中管理 + 即时提示 | PowerToys 专属子系统（跨模块冲突索引+响应对话框）；ShareX 窗口内即时 | ◐ 已显示仲裁归属/冲突状态（保存后可见），**保存前无预检** | 方案 C 的"冲突即时提示（仲裁器预检）"有 PowerToys 级先例支撑 |
| 设置内搜索 | PowerToys（建议跳转）/ CopyQ（命令过滤）/ Flow（插件搜索） | ❌ 无（方案 C-1） | 字段量 <50 时收益中等，维持 C 波次顺位 |
| 高级参数分层 | CopyQ 用独立 Advanced 分类 | ✅ x-advanced 折叠 Expander | 已对齐（折叠比独立页更轻，字段少时更优） |
| 保存模型 | 分裂：CopyQ 提交制 vs PowerToys/Flow 自动保存 | ✅ 保存按钮 + dirty 拦截 | 与 CopyQ 同阵营；ConfigStore 的 Unset 语义与"显式提交"天然匹配，**不改**（评审 §四已定，此处获得对标佐证） |
| 验收/演示工具不进用户面板 | 四家均无此问题（不会暴露 demo 工具） | ✅ C1/C2 已清 | 对标确认方向正确 |
| 总览页（Dashboard） | PowerToys Dashboard（快捷开关+状态总览） | ❌ 无 | 远期可选项：托盘右键"设置"直达的功能页已够用，W7 后再议 |

## 四、对方案 C 波次的优先级修订建议

基于对标，C 波次内部顺序建议调整为：

1. **热键录制控件**（原 C-4）：四家全部"按键捕获"，手打文本是唯一异类；且 W6 实测"默认热键不可注册"后用户自救的第一动作就是改键——录制是热键中心的半成品状态。实现可参照 PowerToys `ShortcutControl`（按钮→对话框→PreviewKeyDown→键徽章预览），是**接收侧**键盘事件（与踩坑 §2.27/§2.29 的注入方向相反，风险低）。
2. **冲突保存前预检**（原 C-4 附带）：调仲裁器预检，录制对话框内即时红字；PowerToys 的 GlobalHotkeyConflictManager 证明这套值得做成宿主级服务而非控件私有逻辑。
3. **设置内搜索**（原 C-1）：字段量过 50 或 W7 工具页暴增后再做，本地过滤即可（PowerToys 也是纯本地建议）。
4. **两列布局/描述常显**（原 C-2）：纯观感，维持最低优先级。
