## 1. 功能概述

**一句话**：复用 W4 遮罩窗骨架，同一个窗两种模式 —— **capture**（拖拽框选 → 位图进剪贴板）与 **pick**（移动放大镜 → 单击取色 → 颜色文本进剪贴板）。

- **产品定位**：Eztools「唤出式工具」家族第四、五员（快搜窗 / OCR / 剪贴板之后）。
- **设计哲学对齐**：单职责窗口、快进快出、零特权（不碰 Core）、全离线、零新 NuGet 依赖。
- **为什么两个功能一波做**：共用遮罩窗/热键/托盘/设置/探针全套基建，分开做就是付两次基建钱。
- **外部参考**（许可纪律：借用先登记 `参考来源.md`）：
  - PowerToys ColorPicker（MIT，工作区自带源码）—— 只抄放大镜 loupe 交互与格式化思路，**不整模块照搬**；
  - Text-Grab / W4-b 既有交互契约 —— 拖拽即出结果、Esc/右键退出、空选区不闪退。

## 2. 需求说明

### 2.1 功能需求（FR）

| # | 需求 | 验收口径 |
|---|------|----------|
| FR-1 | 热键唤出截图遮罩（每屏一扇）；拖拽框选，实时高亮选区 + 像素尺寸标签 | F6 手测 + 探针 |
| FR-2 | 松开鼠标即截图 → **位图进剪贴板** → 气泡提示"已复制 W×H" | 探针 + 手测 |
| FR-3 | 热键唤出取色遮罩（每屏一扇）；移动即放大镜预览（中心像素色值跟随）；**左键单击**复制色值并退出 | F6 手测 |
| FR-4 | 色值格式默认 HEX（`#RRGGBB`），可配置 `rgb` / `hsl`（§5 配置键） | selftest 格式化函数 |
| FR-5 | Esc / 右键 = 全部遮罩退出；识别/截图进行中（busy）忽略新拖拽 | 沿用 W4 契约，手测 |
| FR-6 | 多显示器 + 混合缩放（100%/150%/200% 混搭）下：截图内容与尺寸正确、取色色值正确 | 手工清单双屏缩放条目（W4-b 教训区） |
| FR-7 | 取色准确性：对已知纯色块取色 = 色块定义值（±0） | 手测（对照色块） |
| FR-8 | 热键、色值格式可在设置中配置（`ezt config` + 设置窗口都认） | `--probe-host-settings` 扩展 |
| FR-9 | 托盘子菜单「区域截图」「屏幕取色」两项，与热键同入口 | 手测 |

### 2.2 非功能需求（NFR）

- **NFR-1 全离线 / 零特权 / 零新依赖**：同 W4（§3 论证：取色用 GDI、格式化手写，不引包）。
- **NFR-2 性能**：唤出到可框选 ≤300ms（照抄 W4 实测基线）；放大镜跟随帧率 ≥ 人手可跟（无卡顿感，不做硬性帧率断言）。
- **NFR-3 不碰键盘链**：遮罩窗无文本输入，Esc 走窗内 PreviewKeyDown（W4 已验证路径）；**禁止**引入任何全局钩子（§2.25~§2.30 红线）。

### 2.3 非目标（v1 明确不做，复活条件见路线图）

| 不做 | 理由 |
|------|------|
| 截图标注编辑器（箭头/文字/马赛克） | Snipaste 现成；高成本低差异化（路线图拍板） |
| 屏幕标尺 / 量角器 | 低频（路线图拍板） |
| 跨屏连续选区（一拖跨两屏） | 每屏一扇窗的既有模型下收益低，v1 选区限制在本屏（同 OCR） |
| 截图保存文件 / 历史库 | 剪贴板即终点；要落盘走 W5 图片历史或手工粘贴 |
| 放大镜滚轮变倍 / 取色板 / 调色器 | scope creep |
| CLI 子命令（`ezt capture`/`ezt color`） | 纯 UI 工具，无 headless 场景（D5 可翻案） |

## 3. 整体架构

### 3.1 核心决策：抽基类，不复制窗（D1 推荐 A）

```
Eztools.Desktop（现有宿主，进程模型不变）
 ├─ HotkeyHook / HotkeyArbitration（现有）                      ← 复用，+2 热键注册进来
 ├─ OverlayWindowBase（新增：从 OcrOverlayWindow 抽出公共骨架）
 │    · 全屏置顶半透明 / dim+selection+sizeLabel+hint 四件套
 │    · 坐标纪律：DIP 采集、SourceInitialized 后 GetDpiForWindow 按窗实测、SetWindowPosExact 物理像素
 │    · 交互契约：Esc/右键取消、busy 忽略拖拽、探针采样点（ProbeWin32Rect/ProbeScale/...）
 ├─ OcrOverlayWindow   （改继承 Base，行为零变化）
 ├─ CaptureOverlayWindow（新增：松开 → CaptureService.GrabRegion → Clipboard.SetImage）
 ├─ ColorPickOverlayWindow（新增：loupe + 单击取色 → 格式化 → Clipboard.SetText）
 └─ OcrOverlayManager / CaptureOverlayManager / ColorPickOverlayManager
      （窗列表生命周期 + 完成语义各自持有；先不抽 Manager 基类，三个 Manager 都很薄，过度抽象不如直白）
```

- **为什么抽窗基类而不是复制粘贴**：坐标纪律（W4-b 用血换的）必须单点维护；三份拷贝迟早漂移。
- **为什么 Manager 不抽**：OCR Manager 挂着引擎懒创建/语言过期语义，Capture/Pick 没有这些；强行统一会把 OCR 的复杂度传染给新功能。
- **回归门槛**：W6-a 抽取单独成 commit，`acceptance 341 满额 + verify-desktop OCR 探针 + W4 手工清单` 全绿才许开 W6-b。

### 3.2 数据流

- **capture**：拖拽（DIP）→ 离窗前换算物理像素（Base 纪律）→ `Eztools.Ocr.CaptureService` 既有 GDI 截图按 region 抓取 → `Clipboard.SetImage`（DIB）→ 收窗 + 气泡。
- **pick**：MouseMove → 抓光标周围小块（`CopyFromScreen` 一次 N×N 物理像素， loupe 与取色共用这一份）→ 最近邻放大绘制 + 中心像素格式化 → 左键 `Clipboard.SetText(色值)` → 收窗 + 气泡。

## 4. 交互契约

| 场景 | capture | pick |
|---|---|---|
| 唤出 | 热键 / 托盘「区域截图」 | 热键 / 托盘「屏幕取色」 |
| 预览 | 拖拽高亮 + W×H 标签 | 放大镜跟随（网格放大 + 中心色块 + 色值文本） |
| 确认 | 松开即复制并退出 | 左键单击复制并退出 |
| 取消 | Esc / 右键 | Esc / 右键 |
| 重试 | 无文字概念，不涉及；空拖拽（<4px）视为单击 → 按单击取色？**否** —— capture 空拖拽直接取消出窗（避免两模式语义串味） | — |
| busy | 截图写剪贴板瞬间极短，忽略即可 | 忽略新单击 |

## 5. 设置与接线

| 项 | 值 | 说明 |
|---|---|---|
| 配置键 | `capture.hotkey`（默认 **Ctrl+Alt+X** → ⚠️ **待 D2 重拍；推荐 Ctrl+Alt+B**）、`pick.hotkey`（默认 **Ctrl+Alt+C** → ⚠️ **待 D2 重拍；推荐 Ctrl+Alt+E**）、`color.format`（默认 `hex`） | schema 加在 **Eztools.Host** `HostSettingsSchema`（W4-c 教训：`ezt config` 也要认它，放 Desktop 会两头不认） |
| 热键注册 | 照抄 `RegisterOcrHotkey()` 模式（TrayApplication.cs:524）：TryParse 失败/占用 → 气泡 + 托盘菜单兜底文案 | HotkeyArbitration 已内建 |
| 托盘 | 「屏幕工具」子菜单下加两项（或平铺两项，跟现有风格走） | — |
| 探针 | `--probe-capture-hotkey` / `--probe-pick-hotkey`（真键注入，照抄 `--probe-ocr-hotkey`）；`--probe-overlay` 扩展为可指定模式（ocr/capture/pick），裸泵纪律照抄 §2.27 | verify-desktop 增加对应条目 |
| 默认热键冲突核查 | 🔴 **2026-09-28 运行时实测（推翻原静态结论）**：`Ctrl+Alt+X` 与 `Ctrl+Alt+C` **在本机都注册不了**（`GetLastError=1409`）。原表写的"X、C 经查与系统/常见软件无广谱冲突"是**静态调研结论**，与运行时事实相反 —— 同一台机器上被占的还有 `Ctrl+Alt+W/T/L/R/A/F/Z`（25 个字母里 9 个被占，密度异常高，疑似某个常驻软件批量注册） | **开工前必须重探**：`python -I -X utf8 -u scripts/probe-hotkey-free.py`（已把 X/C 纳入默认探测集）。占用时气泡提示换键 |
| ⚠️ **D2 前提被证伪** | D2 推荐①的两个键都不可用（见上）⇒ **需重拍**。**AI 推荐替代：capture=`Ctrl+Alt+B`（Box 框选）· pick=`Ctrl+Alt+E`（Eyedropper 取色）** —— 两者 2026-09-28 实测可注册 | 定键后回填本表"配置键"行；W6-b 前再探一次（机器状态会变） |

| R4 | 键盘链污染 | 红线：不加全局钩子、不加合成层；遮罩窗 Esc 只走窗内 PreviewKeyDown（W4 已验证） |
| R5 | 热键占用 | 运行时仲裁 + 气泡 + 托盘兜底（照抄既有三件套文案模式）。🔴 **本风险已被实证命中**：2026-09-28 实测 X/C 均不可注册 ⇒ **开工前用 `scripts/probe-hotkey-free.py` 重探并据此定键**（D2 需重拍）；验收侧已改为"被占用计 SKIP 并落数字"，不再伪装成产品失败（见 `docs/代码审查报告-静态守卫首跑-2026-09-28.md`） |
| R6 | loupe 高频重绘卡顿 | 每次移动只 `CopyFromScreen` 一次小块 + WriteableBitmap 局部更新；放大倍数固定（约 8×~10×，D 拍板后固化）；禁止整屏重绘 |

| R8 | 多 TFM 残留目录死产物（§2.31） | 每阶段验收前核对二进制时间戳 + 验收脚本 `$TFM` |

## 8. 待拍板（D1~D6，均有推荐默认，"选 D 编号=选推荐"即可）

| # | 决策点 | 选项 | 推荐 |
|---|---|---|---|
| D1 | 遮罩窗复用方式 | A. 抽 OverlayWindowBase 基类（三窗同骨架）/ B. 复制粘贴独立窗 / C. 单窗加模式枚举 | **A**（坐标纪律单点；C 会把模式分支搅进 OCR 稳定路径，风险最高） |
| D2 | 热键分配 | ① capture=Ctrl+Alt+X、pick=Ctrl+Alt+C ② 两功能共一热键、窗内按键切模式 ③ 只给 capture 热键，取色从托盘/截图窗内进 | **①**（模式切换省的两个键换来每次多一步，高频工具不值；③ 取色也得天天进托盘）。🔴 **前提已被运行时证据证伪（2026-09-28）**：X 与 C 在本机都不可注册 ⇒ **形式仍是①，只是要换键**。**AI 推荐：capture=`Ctrl+Alt+B` · pick=`Ctrl+Alt+E`**（实测可注册）；若不想再挑键，可退选② |

| D4 | 色值格式 | A. 默认 HEX + `color.format` 配置（hex/rgb/hsl 三选一）/ B. 一次复制三格式换行拼接 | **A**（B 粘进代码还要手删，反人类） |
| D5 | CLI 面 | A. v1 不做 CLI 子命令 / B. 加 `ezt capture screen <out.png>` | **A**（无 headless 场景；真需要时窗口模式截图工具遍地都是） |

## 9. 验收策略

- **selftest**：色值格式化（RGB↔HEX↔HSL 手算精确断言）+ 配置键解析；计数增量进总表。
- **verify-desktop**：`--probe-capture-hotkey` / `--probe-pick-hotkey` 真键注入断言（rc + 落盘 JSON 判据，禁 `grep -q`）；`--probe-overlay` 三模式扩展。
- **手工清单**：`W6-手工验收清单.md`（W6-d 建）——双屏混合缩放取色对照已知色块、截图尺寸/内容核验、热键占用气泡、托盘入口、W5 自产入库观察。
- **门禁**：W6-a 回归门槛（§3.1）不绿不开 W6-b；每阶段三件套跑满再开下一阶段。
