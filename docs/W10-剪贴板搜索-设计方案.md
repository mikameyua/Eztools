## 1. 功能概述

**一句话**：两个新 provider——① `clip`：Launcher 里直接搜剪贴板历史，Enter **直贴**回原前台；② `cmd`：`>` 前缀触发系统命令（锁屏/休眠/清空回收站）。

- **为什么便宜**：检索用 W5 现成 SQLite+FTS5 双路搜索（`HistoryStore.Search`），直贴用 W5 面板已真机验证的 `PasteBack`（在 Eztools.Clipboard **类库**，不必从面板抽），命令 provider 只产 `Launch` 动作（rundll32/PowerShell 表达）——**零新基础设施，纯接线**。

## 2. 底座盘点（已核实符号）

| 需要的能力 | 现成实现 | 位置 |
|---|---|---|

| 条目模型 | `ClipEntry`（Id/Kind/Content/Preview/ImagePath/SourceApp/Pinned/CopyCount/CreatedAt/LastUsedAt） | `src/Eztools.Clipboard/ClipEntry.cs:20` |
| 直贴（还原前台 + 注入 Ctrl+V） | `PasteBack.RestoreForeground / InjectCtrlV` | `src/Eztools.Clipboard/PasteBack.cs` |
| provider 接口 / 白名单 | `ILauncherProvider` + `LauncherProviderRegistry`（加 `Clip`/`Command` 常量进 `KnownIds`） | `src/Eztools.Host/Launcher/ILauncherProvider.cs:84` |
| 查询契约 | `LauncherQuery(Text, Generation, Limit, Substr)`——Generation 原样回传、不自行节流 | `LauncherContracts.cs:62` |
| 复制动作 | `LauncherActionKind.CopyText`（W7-c） | `LauncherContracts.cs:51` |
| 徽标映射点 | `LauncherRowText.cs:185-188`（App ▸ / Calc = / Unit ⇄ / Encode {}——**追加 Clip ⧉ / Command ⌘，不改既有行**） | `src/Eztools.Desktop/Launcher/LauncherRowText.cs` |
| 现默认白名单 | `DefaultLauncherProviders = "files,apps,calc,unit,encode"` ⇒ **加 `clip,cmd`** | `HostSettingsSchema.cs:55` |

## 3. 架构

```
Eztools.Host/Launcher/ClipProvider.cs（新增，纯逻辑零 UI）
 ├─ ctor(HistoryStore store)——复用 EnsureClipStore() 同一实例（与面板/CLI 同库 WAL 并存）
 ├─ Id="clip" · IsReady=true（clip.enabled=false ⇒ 装配层不进集合，同 apps 惯例）
 └─ QueryAsync(query, ct)：
      Task.Run(() => store.Search(query.Text, query.Limit))
        → 只取 Kind==Text（D3：图片条目 v1 不收录）
        → LauncherItem(Kind=Clip, Title=Preview 截断, Subtitle="来源 {SourceApp} · {LastUsedAt}",
            Score=0 不参与段内重排（D5，与 W5 面板同序零新逻辑）,
            PrimaryAction=PasteBack(Content), SecondaryAction=CopyText(Content))
      Text 为空 ⇒ 空结果（防御，不倒历史）

Eztools.Host/Launcher/CommandCatalog.cs（新增，纯函数——selftest 穷举）
 └─ static IReadOnlyList<CommandEntry> Entries  ·  static CommandEntry? Match(string input)
    CommandEntry(Name, Aliases, Description, Destructive, LaunchExe, LaunchArgs)
    触发：输入以 ">" 开头（">" 后去空白；不用裸词触发——apps 里 "cmd" 会命中
    Command Prompt，裸词必然歧义）。">" 单独输入 ⇒ 列全部命令（发现性）。
    v1 命令表（三条，关机/重启等高危不进表）：
      锁屏       → rundll32.exe user32.dll,LockWorkStation
      休眠       → rundll32.exe powrprof.dll,SetSuspendState 0,1,0
      清空回收站 → powershell -NoProfile -Command "Clear-RecycleBin -Force"   [Destructive]

Eztools.Host/Launcher/CommandProvider.cs（新增）
 └─ QueryAsync：">..." ⇒ Match 精确/前缀匹配命令表
      → LauncherItem(Kind=Command, Title=命令名+描述, Destructive ⇒ 标题带「（不可恢复）」,
          PrimaryAction=Launch(LaunchExe, LaunchArgs))   ← ★ 零新动作代码

契约变更（最小集）：
 ├─ LauncherKind += Clip, Command
 ├─ LauncherProviderRegistry += Clip="clip", Command="cmd"（KnownIds 同步——白名单错误文案取它）
 ├─ LauncherActionKind += PasteBack（第六动作；cmd 走既有 Launch，零新动作）
 ├─ DefaultLauncherProviders = "files,apps,calc,unit,encode,clip,cmd"（D1+D6）
 └─ LauncherRowText 徽标 += Clip ⧉ / Command ⌘（只加分支）

Eztools.Desktop/Launcher/LauncherActionRunner.cs：+= PasteBack 分支
 └─ 执行序（★ R4 铁律）：SearchWindow 先 Hide → RestoreForeground(preSummonHwnd) → InjectCtrlV()
SearchWindow（★ 预期内接线，仅此一处）：Summon() 开头 GetForegroundWindow() 存 _preSummonHwnd，
    经 Execute 的 PasteBack 上下文传给 Runner（W5 面板 _lastForeground 同款语义）。
    _preSummonHwnd 为空（探针直启）⇒ PasteBack 降级为 CopyText + 状态行说明。
```

**装配**（`TrayApplication.EnsureSearchWindow` 字典加两行）：
`[LauncherProviderRegistry.Clip] = () => new ClipProvider(EnsureClipStore())`、
`[LauncherProviderRegistry.Command] = () => new CommandProvider()`。
依赖方向：两个 Provider 均在 Host 层只碰 Clipboard 类库/纯表——过 G7 分层守卫。

**隐私边界**：provider 只**读** W5 既有库；入库侧黑名单/UIPI 占位/暂停开关原样生效（不重复实现也不绕过）。`clip.enabled=false` ⇒ clip 段静默缺席（装配闸，不占位不报错）。

### 4.2 NFR / 非目标

- NFR-1 零新依赖 · NFR-2 不碰键盘链（`InjectCtrlV` 是 W5 M1 真机验证过的系统级粘贴注入，且发生在窗口 Hide 之后）· NFR-3 SearchWindow 除三处预期内接线外零改动。
- 非目标：图片条目 OCR 动作（涉 Host→Ocr 依赖方向，第二批）；历史编辑/删除（走面板）；`>` 之外的自然语言命令触发；关机/重启等高危命令（**不进表**）。

## 9. 落地记录（W10-a，2026-10-03）

### 9.1 三处方案调整（实施中发现的硬约束，按最优推荐方案实施）

| # | 原方案 | 实际约束 | 调整后 |
|---|---|---|---|
| **A1** | `ClipProvider` 落 `Eztools.Host/Launcher/`，ctor 直接持有 `HistoryStore`（§3） | **TFM 硬约束**：`Eztools.Host` 是平台中立 `net10.0`（`Directory.Build.props` 全仓统一），而 `Eztools.Clipboard` 是 `net10.0-windows10.0.19041.0` + `UseWPF`（要读系统剪贴板）。**低 TFM 引用不了高 TFM** ⇒ 编译不过（与代码风格无关） | **依赖倒置**：Host 声明 `IClipboardHistorySource` + 中立投影 `ClipHistoryEntry`（`ClipboardHistory.cs`），`ClipProvider` 依赖抽象；真实实现 `ClipboardHistorySource`（包装 `HistoryStore`）落 **Desktop**。收益：provider 全部逻辑留在平台中立层 ⇒ `ezt selftest` 可直接驱动（正是 §7 的要求） |
| **A2** | `CommandProvider` 产出 `Launch(LaunchExe, LaunchArgs)`，"零新动作代码"（§3） | 既有 `LauncherAction` 只有**一个** `Argument` 字段，装不下"可执行文件 + 参数" | 给 `LauncherAction` 加**可选** `Arguments`（默认 `null`）—— 既有构造点零改动（apps 的 Launch 行为逐字不变）；`LauncherActionRunner.BuildLaunchStartInfo(path, arguments)` 支持命令行参数 ⇒ cmd 的 Enter 在 W10-a 即打通 |
| **A3** | clip 结果并入既有段（隐含） | ① 并入 pin 段 ⇒ `OrderSegment` 按 Title 重排，**违反 D5**（要求 store 返回序）；② 并入 files 段 ⇒ `filesTotal`/`filesElapsed`/`FilesHitCount` 被 clip 污染，状态行"显示 N / 共 M 条"的数字语义变错（S9 家族） | 新增 `LauncherSegment.Clip`（**原序透传**，与 files 同款不重排）；`QueryRouter.Merge` 段序 `pin → apps → clip → files`；clip **不参与** files 专属计数 |

> ★ 这三处正是本文档 §波次定位所预言的"W7 provider 抽象的外延张力"：**抽象确实缺了一块**
> （provider 需要一个平台相关的数据来源）—— 缺陷本身即本波最重要产出，已记入
> `踩坑全集.md` §2.40。

**另补两处设计文档未展开、但 FR-5/FR-6 要求的落地细节**：

- **`clip.enabled=false ⇒ clip 段静默缺席`**（FR-5）：判定抽成纯函数
  `LauncherProviderSet.ApplySwitches(providers, clipEnabled)`（Host 层），`TrayApplication` 装配前调用。
  ★ 抽纯函数不是洁癖 —— "段位静默缺席"的开关失效**不报错**（S2 家族），留在 UI 装配里没人能钉住它。
- **库损坏不拖垮搜索窗**（FR-6）：适配器**惰性建库**（`Func<HistoryStore>`，`Search` 时才取），
  建连/建表失败只让这一次查询抛 ⇒ `QueryRouter` 隔离成"clip 段暂不可用"；若在构造期建库，
  异常会沿 `EnsureSearchWindow` 冒上去 ⇒ **整个搜索窗建不出来**。

### 11.2 ★ 暂停闸的"断言守副本"缺口（本轮发现并修复）

**症状**：selftest 第 14 例断言 `PrivacyFilter.Evaluate` 的三态（`Allow`/`Blocked`/`Paused`），
但托盘的 `OnClipboardUpdate` **判暂停走的是 `_clipFilter.Paused` 直判**（另一条表达式）——
`Evaluate` 的 `Paused` 分支从生产路径**永远够不到**。后果：**把那行 early-return 删掉/改坏，全绿**，
而"暂停捕获"实际失效（菜单照样切成"已暂停"、气泡照样弹，内容却继续入库）。

**这是 S 家族的教科书形态**：断言守着一份副本，生产走另一条路。与 §9 的 TFM 教训同宗 ——
**"测试绿"证明不了"生产对"，要先问"断言跑的是不是生产那一行"**。

**修法**（最小、零行为变更）：生产改用断言覆盖的那条表达式 ——
`if (_clipFilter.Evaluate(sourceApp: null) == PrivacyDecision.Paused)`。
传 `null` 是因为此刻**还没读剪贴板**（暂停期连内容都不碰），拿不到来源进程；而 `Evaluate` 对 `null`
返回 `Allow`（"不知道来源"不等于违规），所以**等价于只判暂停**，行为逐字不变。
配套 selftest 新增一例把这条表达式的**两个取值**都钉住（暂停 ⇒ `Paused`，恢复 ⇒ `Allow`）。

> **残留（如实登记）**：纯函数断言**守不住"调用方忘了调它"** —— 这与 W10-a 的 `ApplySwitches`
> （W10-17）是同一类残余风险，本波不为它再引入集成探针。理由：探针的监听回调**不是**
> `OnClipboardUpdate`，要真跑生产那一行就得让探针用真 store 起真监听（会写用户真实库），
> 成本/风险不成比例；且该闸失效是**用户可见**的（菜单说"已暂停"却仍在记），手工一眼可辨。
> 故 M4 保留为手工项，但**规则本身**已机器可断言。

### 12.2 C1 实现：**Host 只声明动作，OCR 依赖留在 Desktop**

设计沿用 W10-a 的依赖倒置（那里是 `IClipboardHistorySource`）：

- 执行：`LauncherActionRunner.RecognizeImageText`（读盘 → `WindowsOcrEngine` → 文本），

而 `HistoryStore.Search` 长查询走 FTS（索引**只有 content**）、短查询走 `content LIKE` ——
**两条路都结构性地搜不到图片**。所以必须有一个显式入口：

- 触发词 = **`图片` 或 `img`**（trim 后**精确**匹配，忽略大小写）⇒ 走新的 `IClipboardHistorySource.ListImages`

- 主动作 = `OcrCopy`；**次动作刻意留空**（图片没有"可复制的文本"，造一个语义含糊的次动作不如明说没有）。
- 路径缺失（旧记录 / 图片已被保留期清掉）⇒ 主动作 `null` ⇒ 渲染层走既有"该结果不可执行"
