## 二、A1：编辑器行轻修

1. **CheckBox 语义倒挂修复**（评审 P6-3）：`MakeBoolean` 把 CheckBox 的 Content 从整段 description 改为**字段标题**（label 与勾选框合一），description 只留 ToolTip —— 两行文本改动，渲染树不变大。
2. **secret 状态显示**（P6-5）：`MakeSecret` 已算出的 `configured`（现在塞在 Tag 里）旁边渲染一个 12px 文本（"已配置"/"未配置"），一个 Label，无新原语。
3. **不做**：描述常显、行内错误文本、三层结构。

断言面：selfcheck「键=控件类型」不变，verify-desktop 无感。

## 三、A2：热键捕获式 TextBox（本波核心）

**原则照抄四家（热键绝不手打），形态取最廉价的**：不加新控件，给热键中心的 8 个 TextBox（宿主 5 + 工具 3，B-2 既有）挂捕获行为：

- `PreviewKeyDown`：修饰键（Ctrl/Alt/Shift/Win）+ 主键（A-Z/0-9/F1~F12）→ 组合成键串；
- **规范化必须走 `HotkeyCombo.TryParse`**（与仲裁器 / `ezt hotkeys` 同一份解析——两视图同源纪律），把规范化结果回填 `Text`；
- Esc = 还原进入聚焦前的值；只按修饰键不放行（`Text` 提示"再按一个主键"）；
- 其它输入源（粘贴/程序化赋值）不受影响——`ProbeSetField` 照旧设 `Text`，**探针/自检/verify-desktop expected 零改动**（§六-3 的挂死与断言迁移风险整体消除）。

落点：`SettingsWindow.cs` 的 `RenderHotkeysCenter`（建行处挂事件）+ 一个私有捕获辅助方法。不新增文件。

断言面：零变化（控件类型仍是 TextBox）。真机录制行为靠手测（headless 不覆盖按键，沿用诚实口径）。

## 四、A3：热键冲突即时提示（页内）

- B-2 渲染时已构建 claims + `HotkeyArbitration.Arbitrate`（行内"✓生效/✗让给X"）——A2 的捕获确认与 TextChanged 时，**用当前编辑值替换对应 claim 后重算**，冲突行标红（✗ 前缀 + 让给谁）；
- 不抽服务、不新增文件；只提示不禁止保存（仲裁器"保留先注册者"语义不变）；
- 若将来热键条目增长到需要托盘/CLI 复用同一预检，再抽 Host 级（挂起到待决清单，现在不做）。

### 捕获行为细节（与方案的偏差说明，均为实现期自主决策）

1. **纯修饰键"Text 提示"未做**：临时提示文本会被 TextChanged 当成编辑值（污染 dirty 与保存链）——改为**忽略不写**，无临时文案；
2. **覆盖面扩大**：捕获挂所有 `.hotkey` 字段（含功能域页），不只热键中心——同一判定逻辑顺带覆盖，避免"同一字段两处行为不一致"；
3. **导航键放行**：Tab/方向键/Enter/PgUp/PgDn/Home/End 不捕获（键盘用户不能被困死）；Esc 还原聚焦前的值；
4. **Alt 系统键坑**：Alt 按下时 WPF 把 `e.Key` 报成 `Key.System`——真键在 `e.SystemKey`，已处理；
5. **不支持的主键与多余输入一律吞掉**（`e.Handled = true`）：热键框没有"手打文本"合法路径，粘贴/探针赋值不受影响；
6. **规范化唯一出口**：`HotkeyCombo.TryParse`（与仲裁器 / `ezt hotkeys` 同一份解析）。
