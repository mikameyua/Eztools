## 0b. 托盘正式入口与设置（W4-c）

| 入口 | 说明 |
|---|---|
| 全局热键 | **Ctrl+Alt+O**（默认）唤出遮罩 —— 失败（组合键被占/解析错）时气泡提示 + 日志，托盘菜单是兜底 |
| 托盘菜单 | 「屏幕取字…（Ctrl+Alt+O）」点击即唤出（热键未注册时文案降级并注明） |
| 设置窗口 | 托盘右键 → 设置 → 左列表第一项「**桌面宿主**」：搜索热键 / 屏幕取字热键 / OCR 识别语言三项。**保存即生效**（热键自动重注册；OCR 语言下次唤出生效） |
| CLI 同一文件 | `ezt config get/set desktop <键>` 改的就是 `config/desktop.json` —— 与设置窗口同一条 P1a 链（校验/原子写/损坏恢复共用） |
| 复制反馈 | 成功后托盘气泡「已复制 N 字符」；行数 > 1 时附「多栏排版可能乱序（已知局限）」（§2.3） |
| OCR 语言 | 设置里写 BCP-47 标签（如 `zh-Hans-CN`），留空 = 自动；**配置了未安装的语言时唤出会明确报错**（气泡列出可用语言），不会静默回落 |

**改键立即生效的验证（自动化已覆盖注册面，热键手感 1 分钟可选）**：设置 → 桌面宿主 → 屏幕取字热键改成 `Ctrl+Alt+K` 保存 → 直接按 Ctrl+Alt+K 应唤出（无需重启托盘）；改回默认同理。

> **✅ 2026-09-26 起，本节两条核心手工项已进自动化**（verify-desktop 1c-6 段，135/135）：
> · **改键生效链** → `--probe-host-settings`（程序化走真实设置窗口：改 Ctrl+Alt+K → 保存 → 生效 → 恢复默认，无副作用）；
> · **热键唤出→Esc 收窗** → `--probe-ocr-hotkey`（keybd_event 真注入 Ctrl+Alt+O → 遮罩 → 真注入 Esc 收窗，遮罩抢焦点 1~2 秒）。
> 人工只剩"手感"：真实按键的延迟/气泡观感，与 M1 双屏一样属可选复核。

## M1 多显示器混合缩放坐标（R2 · ✅ 已全自动化验证，人工复核可选）

**✅ 自动化已验证（2026-09-26 02:50，笔记本 175% + 外接 100% 扩展模式）**：探针 `ok=true`、monitors=2、`dpiScales=[1.75,1]`、`placementAllMatch=true`（两扇窗 Win32 位置与预期物理矩形一致），且**外接屏端到端**：在外接屏校准词上真拖拽（剪贴板=外接屏真实文字「助 理」）+ 真点击取词（抄出终端真实路径）。生产"副屏坐标原点"修复（窗口内部坐标 + 窗口 Win32 原点 = 虚拟桌面坐标）被双屏端到端证实。
**人工复核（可选，1 分钟）**：`--ocr-show` 唤出 → 每屏拖一次有字区域 → 粘贴对照（粘出该屏真实文字即过）。⚠️ 每次捕获覆盖剪贴板（标准语义），**每屏一轮"跑命令→拖框→立即粘贴"**，别连截两屏再一起粘。自动化已覆盖机器可判定的全部判据，此项只差"人眼最终确认"。

**失败形态对照**：粘贴出邻屏内容 = Left/Top 未按各自 DPI 换算（查 SetWindowPosExact 是否被跳过）；选区框滞后于鼠标半个身位 = Scale 取了主屏值；`placementAllMatch=false` = 摆放对账失败，看 `placement` 数组里 intended/actual 差多少。

## 症状速查

| 你看到的 | 真实病因 | 修法 |
|---|---|---|
| 探针 rc=3 且零输出 | **托盘已在跑**（单实例锁，§G2-a 前科） | 先退出托盘再跑探针 |
| 遮罩出现后探针卡住 | 遮罩抢了焦点而探针在等窗关 | Esc 一下；探针 8s 超时会自愈 |
| 鼠标"自己动了" | `--probe-ocr-overlay` 的真注入副作用（预期） | 无人交互时跑 |
| 粘贴出的文字与上次不同 | 剪贴板被探针/其他程序改写（预期副作用） | 以探针 JSON 的 `clipboardText` 为准 |
| 每次识别都报「识别失败」 | 语言包被卸载（R1） | `ezt ocr langs` 复查；为 0 则按其引导装 Feature |
| JSON `warnings` 里有「关闭 OCR 遮罩窗失败（忽略）」 | 收窗竞态的良性告警（Close 撞上正在关闭的窗，已被捕获忽略） | 无需处理；出现频繁再查 |
