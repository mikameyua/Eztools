> **用途**：记录本项目借鉴过的外部实现、它们的许可、以及需要保留的声明。
>
> **为什么必须有这个文件**：
> ① 本仓库许可是 **`GNU General Public License v3.0 or later`**（2026-09-21 拍板，见 `LICENSE`）——
>    **是 OSI 开源许可**，允许商业使用；对外就该写 **"open source"**。
>    仍须能说清"哪些代码是从哪儿来的"（外部代码的版权声明必须保留）；
> ② **许可是有传染性的**，事后再补极其麻烦；
> ③ 判断"能不能抄"必须在**动手之前**做，不是之后。

## 一、怎么判断能不能用

| 许可 | 能怎么用 | 注意 |
|---|---|---|
| **MIT / BSD / Apache-2.0** | ✅ 可读、可抄、可改、可融进产品 | **只需保留版权声明**（源码里或 `NOTICE` 文件） |
| **GPL-3.0** | ✅ **可读、可抄、可改、可移植** | 本项目自己就是 GPL-3.0，**同许可 ⇒ 无污染问题**。义务 = 保留原作者版权声明；抄进来的文件即成为 GPL-3.0 的一部分 |
| **GPL-2.0-only / AGPL-3.0** | ⚠️ 仍**只读文档、不读源码** | GPL-2.0-only 与 GPL-3.0 **不兼容**（抄进来是无法调和的冲突）；AGPL-3.0 技术上可并入（GPL-3.0 §13），但其 §13 网络条款会附着在该部分上 → **默认避开** |
| **LGPL** | ⚠️ 可链接，但改动库本身的部分要回馈 | 界线在"链接"而非"调用"；**用独立进程调它的 CLI 通常安全** |
| **MPL-2.0** | ⚠️ 文件级 copyleft | 改了它的哪个文件就要公开那个文件 |
| **MPL-1.1** | ❌ **不能用**（与 GPL-3.0 不兼容） | FSF：GPL 模块与 MPL-1.1 模块**不能合法链接**。唯一例外 = MPL 1.1 **§13** 另列 GPL（或其他 GPL 兼容许可）为备选许可。⚠️ **与上面的 `MPL-2.0` 不是一回事**：MPL-2.0 默认兼容 GPL |
| **闭源 freeware** | ❌ 无源码可参考；❌ 不宜当组件打包 | 有些允许二进制再分发（需署名），但那不等于"能当自己的组件" |
| **公共领域 / Unlicense / CC0** | ✅ 随便用 | 少见 |

**三种"参考"的界线**（法律后果差很远）：

| 做法 | 是否触发许可 |
|---|---|
| **调用**别人的程序（CLI、本地 API、SDK 的 IPC 通道） | 通常**不构成分发**，一般不触发 |
| **抄代码**进自己的项目 | **必然触发**，看许可决定后果 |
| **学思路**自己实现（只看文档与行为） | 著作权保护"表达"、不保护"思想/功能"，一般**不触发** |
