## 1. 问题定义（"沉默"，与 W8 的"说假话"互补）

索引可**热加载**（`search.status` 回 `ready=true`，自举快照在）而提权 Core **随后退出**——此时：

- 查询一切正常（不触发 W8 的 `-32001` 分流路径）；
- USN 增量无人应用 ⇒ 索引**停止更新**：旧文件搜得到、**新文件搜不到**；
- UI 的"启动核心服务"出口只在 `Ready=false` 时出现，而陈旧态恰好 `ready=true` ⇒ **出口消失**。

实测证据（10-02 还原快照 vs 当天重建）：**1,892,376 vs 1,911,112 条**——约 1.9 万条近期文件搜不到且无从察觉。

## 2. 判据与手段

| 判据 | 手段 |
|---|---|
| "索引自称就绪" 与 "核心服务实际状态" **同时**可得的地方 | `SearchWindow.ApplyVolumeSummary` 的 **Ready 分支**——每次唤出必经（`Summon → RefreshVolumeSummary → status 往返`），且 W8 的探测函数（`coreAvailability`）W8 落地时就已注入窗口，**托盘零改动** |
| 陈旧时说什么、给不给出口 | 新纯函数 `CoreStaleNotice`（`src/Eztools.Host/Launcher/`，selftest 可穷举）|
| 保守性继承 W8 | `CoreOk` 正常、`Unknown` **闭嘴**——探测说不清绝不制造假警报或点了没用的按钮 |

## 3. 两个可见出口（不新造 UI 元素）

1. **状态行主出口**：陈旧时 `_status` 让位给提示（原信息挪右栏，一个字不丢）；空查询/有结果/无匹配三态都让位。
2. **卷清单行行尾后缀**：`· ⚠ 核心服务未运行，索引已停止更新`（与卷漂移提示 §7.4.1 同款打法）。

## 4. 实施决策记录（含两处自主决策）

| # | 决策 | 理由 |
|---|---|---|
| D-a | **CoreNotElevated 陈旧提示刻意不可点**（与 W8 错误路径的 `CanLaunch=true` 不一致） | 核心服务活着时 `CoreLauncher.LaunchElevatedAsync` 幂等回 `AlreadyRunning`（"已在运行"）——点了没用还重建一次注定失败的自举。指引写进文案（"请以管理员身份重启核心服务"）。⚠ W8 错误路径的同款半吊子行为**只登记不修**（不扩大已收口波次范围，见台账） |
| D-b | 陈旧态下"X ms / 没有匹配"**挪右栏不丢弃** | 提示比统计重要，但信息不能消失（S9 家族：丢了 = 另一种沉默） |
| D-c | 探测只取**一次**（`coreNow` 局部变量） | 两次调用可能跨 2s 缓存边界拿到不同结论 |
| D-d | `CoreOk` 恢复时状态行**立即还原占位文案** | 否则旧陈旧提示挂到下次查询才消失（"显示了但显示的是错的"） |

## 6. 已知边界

- 核心服务在窗口**开着期间**退出：下一次唤出才探测到（窗口无轮询）——可接受（唤出频率 >> 退出频率；轮询是"正在努力"假象的同族反模式）。
- 陈旧提示判据不区分"索引从未建好"与"建好后停更"：前者首个击键即触发 W8 精确文案，两者指向同一出口，不冲突。
- 沙箱内跑 verify/acceptance 会被静默杀 ⇒ 必须 `dangerouslyDisableSandbox`；热键被外部程序占用时（`probe-hotkey-free.py` 判定）热键类断言按占用计数，判据仍是 FAIL=0（扣除环境项）。
