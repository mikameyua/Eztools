## 准备：启动托盘（30 秒）

**启动方式（2026-09-19 已根治）**：`DOTNET_ROOT` 已写入**用户级永久环境变量**（指向 `D://dotnet10`）——
**新开的终端不用再 export**，直接跑 exe 即可。两个注意：

- **已开着的旧终端**不继承新变量，仍需手动 export；**双击 exe** 要等资源管理器重启后才会拿到新变量
- 若弹出 **"要下载 .NET 吗"** 的框 → 那是宿主找不到运行时时的提示，**点 No/取消关掉**，不要下载
  （机器上已有运行时，下载反而多装一份系统级的）

```bash
cd /d/01-项目代码/Eztools
./src/Eztools.Desktop/bin/Debug/net10.0-windows/Eztools.Desktop.exe &
# （旧终端里跑才需要前面加 export DOTNET_ROOT="D:/dotnet10"）
```

**① 该看到**：任务栏通知区域出现图标——**默认在溢出区**（小三角 `^` 里），并弹一次气泡提示"图标在任务栏通知区域（可能在溢出区…）"。
**验什么**：单实例锁、图标注册、首次溢出区提示（提示只弹一次是设计行为，第二次启动不会再弹）。
**⚠️ 实测踩过**：粘贴命令块后**要按回车**（最后一条不回车 = 没执行，表现为"跑了但什么都没发生"）；
启动后终端**别关**（关掉终端 = 托盘一起退出）。若自动化测试先跑过，气泡会被"只弹一次"标记消耗——
那时不会看到提示，属预期；要重新体验就删 `%LOCALAPPDATA%\Eztools\.tray-hint-shown` 再启动。
**不对时**：图标完全没出现 → 查上面日志文件有没有启动记录；连气泡都没有但进程在 → 记下来，可能是气泡时序问题。

**② 顺手做**：把图标从溢出区拖到任务栏常驻区（Win11 允许固定）。后续步骤点击方便。
**验什么**：无。纯操作便利。

## B. 设置窗口（P1b 核心）

**④ 点「设置…」**
**该看到**：一个 Fluent 风格（浅色主题）窗口：左侧列表 **echo / filehash / wordcount**（3 个，probe 没有 config 不出现），右侧是第一个工具的字段表单。
**验什么**：WinForms 消息循环上 WPF 模态窗口能正常打开（两栈共存的真实交互路径）；schema 驱动的工具发现（"新工具声明 config 就自动出现"——本窗口无一行工具专属代码）。
**不对时**：窗口白板/无样式 → iNKORE 主题资源没挂上（记截图给我）；左侧少工具 → 该工具 schema 解析失败，查日志。

**⑤ 逐个点左侧工具，核对字段与控件**

| 工具 | 字段 → 控件 |
|---|---|
| echo | uppercase → **开关（CheckBox）** |
| wordcount | countWhitespace → 开关 · language → **下拉（auto/cjk/latin）** · maxFileSizeMb → **文本框**（悬停显示"范围：1 ~ 1024"） |
| filehash | algorithm → **下拉（sha256/sha1/md5/blake2b）** · uppercase → 开关 · chunkSizeKb → 文本框（范围：4 ~ 65536） |

**验什么**：§7 映射表（boolean→开关 / enum→下拉 / integer→带范围提示的文本框）在真实 UI 上的观感。自动化已断言过控件类型，这里看的是**渲染质量和文案**。

**⑥ 改值 → 保存 → 对账**（⭐ 审查修复点：提示可见性）
1. 选中 echo → 把 uppercase 开关**勾上** → 点「保存」
2. **该看到**：顶部提示条出现 **"已保存 1 项（HH:mm:ss）。transient 工具下次调用即生效。"**
   → 审查修复前这条提示会被立刻覆盖、永远看不见；现在应该稳定显示
3. 另开一个终端对账：
   ```bash
   cd /d/01-项目代码/Eztools && export DOTNET_ROOT="D:/dotnet10"
   ./src/Eztools.Cli/bin/Debug/net10.0/ezt.exe config get echo uppercase    # 期望 true
   ./src/Eztools.Cli/bin/Debug/net10.0/ezt.exe invoke echo.echo --text hi   # 期望 "HI" —— 配置真的注进了工具
   ```
4. 回窗口把开关取消勾选 → 保存 → 再对账（期望 false / "hi"）

**验什么**：窗口与 CLI 改的是同一个文件；保存 → 落盘 → 工具注入的完整数据链路。

**⑦ 非法值要被拒**
选中 wordcount → maxFileSizeMb 填 **99999**（上限 1024）→ 保存。
**该看到**：弹"部分字段未保存"警告框，列出 `maxFileSizeMb: …超过上限…`；**其余合法字段照常保存**。
**验什么**：校验在 ConfigStore 层统一生效（窗口不自己写校验），失败不落盘。

**⑧ 快速双击「保存」**（⭐ 审查修复点：重入防护）
连续快速点两次保存按钮。
**该看到**：无异常、无重复弹窗；保存过程中两个按钮是**灰色禁用态**。
**验什么**：审查修复 2——await 期间窗口仍可交互，不挡的话会并发两次写盘+推送。

**⑨ 恢复默认 = 破坏性操作**（⭐ 审查修复点：备份式重置）
1. 先随便给某工具设几个值并保存
2. 点「恢复默认」→ **该看到确认框**："…当前配置会备份为 .reset-backup-* 文件，不会丢失"
3. 点确定后核验备份真的存在：
   ```bash
   ls "$APPDATA/Eztools/config/" | grep reset-backup    # 期望：echo.json.reset-backup-<时间戳>
   ```
**验什么**：审查修复 1——重置不再裸删（此前误点 = 配置永久丢失）；确认框拦截误操作。

**⑩ 关闭窗口 → 再打开**
点 ✕ 关闭，再点「设置…」重开。
**该看到**：窗口正常重开，字段显示的是**当前落盘值**（不是上次编辑未保存的草稿）。
**验什么**：模态窗口生命周期干净，每次打开重新加载快照（关窗口不会误触发程序退出——`ShutdownMode` 语义正确）。

## C. 共存与隔离（两栈互操作的稳定性）

**⑪ 窗口开着时同时调工具**
设置窗口保持打开，另开终端连跑几次：
```bash
cd /d/01-项目代码/Eztools   # ⚠️ 家目录下相对路径会报 No such file（实测）
./src/Eztools.Cli/bin/Debug/net10.0/ezt.exe invoke echo.echo --text "共存测试" --quiet
```
**该看到**：CLI 正常返回，窗口无卡顿无闪退。
**验什么**：WinForms 托盘循环 + WPF 模态泵 + 宿主调用线程三者并存——这是探针验证过的组合，这里验的是**长时间真实使用**下的表现。

**⑫ 托盘菜单的工具项真实点击**
先复制一段文本（随便什么），然后托盘 → 文本统计 → 统计文本。
**该看到**：气泡反馈 + 工具真的把剪贴板内容统计了（结果看日志或气泡）。
**⚠️ 气泡可能不显示**：Win11 把托盘气泡转成系统通知，勿扰/专注助手开着或该应用通知被关时会
**静默丢弃**（实测：气泡没出现，但日志里三次调用全部成功）。两条出路：
1. 设置 → 系统 → 通知 → 关掉"勿扰"，允许 Eztools.Desktop 通知
2. 直接看日志（程序已把结果写进日志，不依赖气泡）：
   `tail -5 "$LOCALAPPDATA/Eztools/logs/host-ezt-desktop-20260919.log"`
   期望：`托盘调用 wordcount.count 完成，用时 …ms，结果 {…}`
**验什么**：`menus.input: clipboard` 契约在真实点击路径上的表现（自动化是程序化触发，这里验真鼠标）。
