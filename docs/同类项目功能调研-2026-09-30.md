## 4. 关键发现

1. **功能交集 = 已做 + 已计划，无漏项。** 头部项目高频功能的交集恰好被 W3/W4/W5/W6/W7 覆盖；本次调研**没有发现"路线图漏掉的高价值功能"**——路线图的三条筛选标准实质上就是头部项目的功能收敛结果。
2. **Launcher 是全行业的收敛点。** PowerToys（Command Palette）、Flow、vicinae 都在把散装功能往一个面板收。这印证了路线图"Launcher 即主入口，其他工具尽量从它进入（缓解 RegisterHotKey 稀缺）"的判断，也印证 **provider 抽象优先于单功能堆砌**——Flow 的价值主要在插件生态而非自带功能数量。
3. **差异化靠质量与本地优先，不靠功能数量。** 闭源免费竞品（Snipaste/Listary/uTools）已覆盖大量功能，筛选标准第③条（无现成免费替代）是"不做"的主要闸门。Eztools 的相对优势在：本地优先、隐私不外传、原生性能（W3 搜索 / W5 直贴已证明）——这与 vicinae 走原生 C++ 路线拿到 10k★ 的信号一致。

## 5. 优先级建议（维持路线图 + 微调）

| 优先级 | 内容 | 依据 |
|---|---|---|
| **P1（下一个开工）** | W6 视觉小波：F1 取色 + F2 区域截图（一个遮罩窗两模式） | 调研确认两者为同类标配；底座（W4 遮罩 + W5 剪贴板）复用最顺；开工前按惯例先跑 `scripts/probe-hotkey-free.py` 重探热键 |
| **P2** | W7 Launcher：provider/action 抽象先行，首批 provider 顺序 **文件 → 应用启动 → 计算器 → 单位换算/编码转换** | 顺序经 Flow/PowerToys Run 的使用率印证（文件与计算器是使用率最高两档） |
| **顺路项** | W5 剪贴板**置顶钉选** | Ditto 的收藏/置顶印证价值；按路线图原样"触碰 W5 时代码顺手加" |
| **观察名单**（不立项，W7 落地后按需评估） | 取色历史（PowerToys 有，实现≈一张 SQLite 表 + loupe 里加一列）；进程结束 provider；窗口切换 provider | 均为头部项目验证过的中频功能，但当前不满足"无现成免费替代" |
| **不做清单** | 建议补一行"**贴图**"（理由同截图标注编辑器：Snipaste 现成） | 防止反复重提 |
